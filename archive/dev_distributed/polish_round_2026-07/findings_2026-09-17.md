### 2.1 The BFS deadlock (root cause)

`partdir` was assigned inside `if rank == 0 ... else nothing end`, so `distribute` dispatched
differently per rank:

- rank 0 got a `String` → `distribute(dir::AbstractString)`, loaded its `.jls`, carried on
- rank 1 got `nothing` → `distribute(mesh; ...)`, non-root branch `MPI.recv(source=0)`, blocked
  forever because the offline path never sends

Presents as a hang with frozen RSS and no `Starting SIMPLE loops...`. It ran 25+ minutes before
being killed. Introduced by `fd9049c0` (a post-gate wip commit) — **not a merge regression**.
`test_offline.jl` passes because it uses the correct idiom (`test/distributed/test_offline.jl:13-16`):

```julia
dir = MPI.bcast(rank == 0 ? mktempdir() : nothing, comm; root=0)  # String on EVERY rank
rank == 0 && partition_mesh(gmesh, nranks; dir)
MPI.Barrier(comm)                                                  # writes complete first
dm = distribute(dir; comm)
```

The example also hardcoded `/home/humberto/Desktop/BFS_GRIDS`, making it unrunnable for anyone
else, and re-partitioned the whole mesh on every launch.

Fix applied to `examples/3D_BFS_mpi.jl` (uncommitted): `partdir` on all ranks + `Barrier`;
default to the packaged mesh with `XCAL_BFS_GRIDS`/`XCAL_BFS_MESH` overrides; reuse an existing
`parts_n<N>/` instead of re-partitioning. Verified standalone from a clean directory (100 iters,
19.9 s, writes `processor0/1` + `XCALibre.foam`) and against pre-made partitions.

## 3. CPU strong scaling

BFS 4mm, 1,320,368 cells, 100 SIMPLE iterations, Cg+GAMG pressure / Bicgstab+Jacobi momentum,
one rank per physical P-core, `julia -t1`, BLAS=1, OMP=1, offline-partitioned, output disabled.
Per-iteration cost is `(t100 - t3)/97`, which cancels the ~24-32 s JIT compile.

```
n=1   293.4 s   2.692 s/iter   1320368 cells/rank   1.00x   100%
n=2   178.8 s   1.592 s/iter    660184 cells/rank   1.69x    85%
n=4   122.9 s   1.010 s/iter    330092 cells/rank   2.67x    67%
n=6   103.5 s   0.818 s/iter    220061 cells/rank   3.29x    55%
```

Full record: `~/.cache/xcal_bfs_scaling/RESULTS.md`. Residuals agree to 4-5 significant figures
across all rank counts, so this is a clean scaling measurement, not correctness drift.

**The cause is not measured.** Candidates: memory bandwidth (single-socket laptop DDR5), GAMG
setup/solve, halo exchange, and sustained-load clock throttling (`lscpu` showed 26% of max MHz,
which alone can produce decay of this shape). Core heterogeneity is ruled out — all runs sat on
P-cores (CPUs 0-15 at 5.6-5.8 GHz; 16-31 are E-cores at 4.1 GHz, so >8 ranks on this box would
fall off a cliff).

Applies to: this laptop, tet mesh, GAMG. Does not necessarily apply to a real node with more
memory channels, or to Jacobi — the docs' own benchmark has Jacobi and AMG crossing near ~1M cells.

## 4. HYPRE through stock PETSc.jl binaries

We reach HYPRE purely via PETSc's options system (`_pc_type(::BoomerAMG) = "hypre"`,
`ext/XCALibrePETScExt.jl:18`), guarded at runtime by `PetscHasExternalPackage`
(`ext/XCALibrePETScExt.jl:110`). The code is therefore library-agnostic by construction —
nothing depends on the custom build.

Stock `PETSc_jll` ships 8 libraries:

- `Float64/Int64` and `Float64/Int32` — **hypre=true**, mumps=true
- all `Float32` and Complex variants — hypre=false
- **cuda=false for all of them**

Verified end-to-end: `test_hypre.jl` **passes at n=2 on stock `PETSc_jll` + `MPICH_jll`**, with
no custom library and no `local_stack.sh`. So `BoomerAMG()` works out of the box for default F64
users. Stock users get the Int64 library (`_petsclib` takes the first `PetscScalar` match); the
custom build here is Int32.

Consequences: F32 users lose hypre, and **GPU-native solve requires a custom CUDA PETSc**.

## 5. Threading per rank

At `-n 4 --bind-to core --map-by core`, every rank reported `julia_threads=1 blas_threads=1`,
pinned to one physical core (HT sibling pairs `0-1`, `2-3`, ...).

- Julia threads default to 1, so the KernelAbstractions CPU backend is already serial. No `-t 1`
  needed, and passing `-t >1` is what would introduce KA overhead.
- BLAS would be **16** by default. It is 1 only because the example calls
  `activate_multithread(backend)`, whose signature is
  `activate_multithread(backend::CPU; nthreads=1) = BLAS.set_num_threads(nthreads)`.
- `OMP_NUM_THREADS` is unset by default; exported as 1 for these runs.

## 6. Environment gotchas

- `--heap-size-hint` changes the precompile CacheFlags hash, so the child precompiling
  `XCALibrePETScExt` requests a PETSc image built under different flags and fails with
  "Precompiled image PETSc not available with flags CacheFlags(...)". Looks exactly like cache
  corruption; clearing `~/.julia/compiled/*/PETSc` does **not** fix it. Use
  `--startup-file=no` and no heap hint.
- `/tmp` is tmpfs (RAM-backed) on this box — never write partitions there.
- Memory ceiling is rank 0 holding the **global** mesh, not the rank count. Offline
  `partition_mesh` in a standalone process removes it. Measured ~1.6 KB/cell (2.5 GB peak for
  1.32M cells), so the 3mm mesh (~2.7M cells) needs only ~5 GB and should fit.

## 7. Recommendations

Before release:

1. Commit the `3D_BFS_mpi.jl` fix. It is the only example exercising GAMG, offline partitioning
   and the OF writer together, and it is broken on the branch as it stands.
2. Wire `test/distributed` into a gate. It is in neither `test/runtests.jl` nor CI, so there is
   no regression net — today's green is a manual snapshot. CI also only runs on `main` pushes and
   PRs, so this branch has never had a CI run at all.
3. Add a CHANGELOG entry for the whole MPI feature. There is currently none.
4. Decide on `MPI` and `Metis` as **hard deps** used only by `src/Distribute`, while `PETSc` is a
   weakdep. Every serial user currently pays for them. Either is defensible; the asymmetry should
   be deliberate.
5. Exercise Julia 1.10/1.11 for `Distribute`. Local is 1.13, CI targets 1.10/1.11, and the module
   has never been run on either.

Worth doing, not blocking:

6. Attribute the scaling loss before optimising: one PETSc `-log_view` run at n=2 and n=6 splits
   KSPSolve / PCSetUp / VecScatter. No code changes, and it turns section 3's hypothesis list
   into a number.
7. Document that GPU-native solve needs a custom CUDA PETSc, since `PETSc_jll` has no CUDA.
8. Fix the error at `ext/XCALibrePETScExt.jl:112` — it tells users to "see
   build_cuda_ucx_openmpi_petsc.sh", a local script they do not have. Point at the docs instead,
   and note that stock PETSc.jl already has hypre for F64.
9. Rename or re-document `activate_multithread`. It reads like it enables threading; it pins BLAS
   to one thread.
10. Consolidate the dev record. `dev/` is gitignored and currently mixes two features:
    `STATE.md`/`SESSION_STATE.md` + decisions D1-D5 are distributed (2026-07-08), while
    `NEXT.md`/`PLAN.md`/`SPEC.md` + D6-D13 are motorBike. `dev/NEXT.md` says "phase 1 motorBike,
    branch HM/slip-boundary-fix" and must not be read as the distributed state. Because `dev/` is
    local-only, `archive/dev_distributed/` is the only copy in git. An `xcalibre-close` pass would
    sort this, and the three GAMG commits need a dev-record entry.
11. Remaining functional gaps: LKE/LES not distributed; `wall_distance!` prints a spurious
    "did not converge"; `convergence` is silently ignored in distributed except as the
    `atol == rtol == 0` fallback.

Not run this session, available on request: the 3mm mesh (see 6 — it fits), the shipped
`write_interval=100` variant (output writing was disabled to isolate solver time, so `t` in the
committed example includes the OF write), and `test_f32`/`test_perf`/`test_scaling`.
